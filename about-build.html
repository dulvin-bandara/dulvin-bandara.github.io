About
This Build

The site is laid out like a CFD package and the hero is a small post-processing viewer. This page says how each part works, and which parts are real data and which are illustration.

Plain HTML, CSS and JavaScript WebGL, no library Python and NumPy for the mesh GitHub Pages

Overview

Problem
A portfolio for aerodynamics software work should show tooling, not just describe it.
Approach
A static site with no framework and no build step: a WebGL viewer for a scanned head mesh, a custom binary model format, and a shell that treats reading the page as a solver run.
Result
7,772 nodes, 15,351 faces and 111 streamlines in a 319 kB file, drawn by under 600 lines of JavaScript, with a fallback for browsers without WebGL.

What Is Real and What Is Not

The head is a real 3D scan of me. The streamlines are not a CFD result: they are a hand-built flow model, there to look right and to show the viewer working. The residual plot, iteration counter and solver tag in the shell are driven by the scroll position and are decoration. Everything on the project pages is real work, with the numbers taken from the reports.

The Head Mesh

The scan came from a phone photogrammetry app as an OBJ file with about 29,000 vertices. It was tilted, attached to a torso, and only covered the left side of my head. A set of Python and NumPy scripts turns it into the model on the home page:

  • Weld. The scan splits vertices along texture seams, so vertices at the same position are merged first. Without this the mesh falls apart into dozens of disconnected pieces as soon as it is cut.
  • Find the centre plane. The face is reflected across a candidate plane and compared with itself. A search over yaw, roll and offset keeps the plane where the two halves match best. It lands through the bridge of the nose.
  • Cut and mirror. Triangles are clipped exactly on that plane, the torso is cut away, and the good half is reflected. The two halves share the vertices on the plane, so there is no seam.
  • Fill the gap. The crown and back of the head were never captured. The surface is sampled as a radius over a sphere of directions, and the missing directions are filled by solving Laplace's equation from the edges inward.
  • Reduce. Vertex clustering on a grid that is symmetric about the centre plane brings the mesh down to 7,772 nodes while keeping both halves identical.
  • Colour. The scan's texture is sampled once per vertex and stored with the mesh, so no image file is shipped.

The Model File

The viewer loads one binary file. A 24-byte header gives the counts, and each block after it is a typed array padded to four bytes, so the browser can read it in place without parsing:

BlockTypeContents
PositionsInt16 × 3Vertex positions, quantised to the model's range
NormalsInt8 × 3Vertex normals, for shading
TrianglesUint16 × 3Indices, which is why the mesh stays under 65,536 nodes
StreamlinesInt16 × 3150 points on each of 111 lines
Speed, wakeUint8Per point: colour-map value and how unsteady the line is there
ColourUint8 × 3Per vertex, from the scan's texture

The Viewer

The hero is drawn with WebGL directly, with no rendering library. Two shader programs do the work:

  • Surface. Each cell is filled first, pushed slightly back in depth, then its edges are drawn on top. That hides the far side of the head without sorting anything. The build sequence is a threshold on height: edges appear above it, and a second threshold brings the colour down after them.
  • Streamlines. Each line is a ribbon of two vertices per point, widened in screen space in the vertex shader so it keeps a constant pixel width. Colour comes from a seven-stop velocity map, pulses travel faster where the flow is faster, and points in the wake sway.

The streamlines themselves are potential flow round an ellipsoid fitted to the head, with separation, a velocity deficit and three scales of eddies added behind it, integrated with fourth-order Runge-Kutta and then pushed off the real surface wherever a line cut through it.

When WebGL Is Not There

WebGL can be missing, switched off, or present but drawing nothing. The viewer checks for all three. If the context is missing or lost, or the canvas is still blank four seconds in, it draws one finished frame with the 2D canvas instead, sorting triangles back to front. Under reduced-motion settings it draws a single still frame and nothing moves.

The Shell

The ribbon, outline tree and status bar are ordinary links and work without JavaScript. With it, the scroll position becomes a solver run: the iteration count and residuals fall as you read, and the console logs each section. The console also takes commands. Open it from the tool row and type help.

How It Was Made

I designed and directed the site and wrote it with Claude Code, an AI coding assistant, which did much of the implementation. The engineering work on the project pages is my own, and the surrogate project keeps its own log of where AI was used.
